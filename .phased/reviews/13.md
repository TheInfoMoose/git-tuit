## Independent pass

### F1. `base: "amber"` (no `Some`) gets the user's theme.ron rewritten — new defect
- **Where:** `src/ui/style.rs:62` (`ThemePatchFile.base: Option<String>`) with the fallback at `src/ui/style.rs:627`.
- **Trigger:** a `theme.ron` whose `base` is written as a bare string, e.g. `(base: "amber")`, or `(base: "amber", selection_bg: "Black")` (every other field in old bare form).
- **Effect:** ron has no `implicit_some` by default, so `"amber"` fails as `Option<String>` and the patch parse errors. `OldThemeFile` has no `base` field and doesn't deny unknown fields, so it ignores `base` and parses fine. The file is treated as an old full-format theme: the user gets classic colors, and `save_patch` overwrites their file with a classic-diff patch, `()` for the first example. The `base` line is gone and nothing says why. At launch, `ThemePatch` had no `base` field and also ignored unknown fields, so the same file parsed as an empty patch and was never rewritten.
- **Siblings:** a lone `base: Some("Amber")` (wrong case) doesn't rewrite anything. It falls to classic with a `warn` (F4). Any other bare-string field mixed with `Some(...)` fields fails both parses and falls back to classic without touching the file. Only "every value bare" files get rewritten.
- **Fix direction:** have the old-format path reject a `base` key (a `base` field on `OldThemeFile` that errors if present, or check `base` before trying the old format), or log the patch error and skip the rewrite whenever the content mentions `base`.

### F2. An existing partial theme.ron no longer fills from amber — regression (deliberate)
- **Where:** `src/ui/style.rs:614` (`None | Some("classic")` → `apply_classic_patch`).
- **Trigger:** a user on a truecolor terminal who already has a partial `theme.ron` from Phase 12 (e.g. `(selection_bg: Some("Black"))`).
- **Effect:** at launch, the unset fields came from amber. Now they come from classic, so the UI flips from amber to classic blue/reset after an upgrade, with no log line. The assertions in `t12b`/`t12c`/attention partial tests were rewritten from amber RGB values to `Reset`/`Yellow` to match. Fixing it means adding `base: Some("amber")`. That's documented, but nothing tells the user it's needed.
- **Class:** regression vs launch. Reads as an intentional product call. See the contract pass.

### F3. THEMES.md opening line contradicts the new fill rule — doc defect (nit)
- **Where:** `THEMES.md:10`, "To change the colors of the default theme you need to add a `theme.ron`…".
- **Effect:** the default theme on truecolor is amber, but adding a `theme.ron` without `base: Some("amber")` drops amber entirely. The same paragraph then says so, so a reader who stops at the first sentence loses amber.

### F4. `base` is matched case-sensitively — new defect (nit)
- **Where:** `src/ui/style.rs:610`.
- **Trigger:** `base: Some("Amber")` or `Some("Classic")`.
- **Effect:** `"Amber"` → unknown base → classic, with a `warn` only in the log. COLORTERM matching just above is case-insensitive (`is_truecolor`), so the two rules don't match.
