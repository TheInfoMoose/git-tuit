## Independent pass

### What changed (read from code)
- New theme fields `canvas_bg` (amber `#000000`, classic `Reset`) and `rule_fg` (amber `AMBER_DARK`, classic `DarkGray`). In patch, old-format and save paths.
- `App::draw` paints the whole frame with `theme.canvas()` before anything else.
- Tab bar: bottom rule and `" | "` dividers use `theme.rule()` instead of `block(false)` (= `disabled_fg`).
- `tab(true)` gains `BOLD` on top of `UNDERLINED`, in both themes.
- Classic base: unset `rule_fg` follows `disabled_fg` (load and `save_patch`), same pattern as `scroll_thumb_fg`.
- Old-format files that set `base` are now resolved through `resolve_patch` (honoring their colors) instead of falling back to bare classic. They are still never rewritten.
- `load_with_notice` returns the no-base notice so tests can check it. `init_for` still only logs it.
- Spinner draws with `theme.spinner()` (fg `selected_tab`, bg `canvas_bg`), captured once in `Gitui::new`.

### Findings

**F1. Unselected tag labels punch terminal-default holes in the amber canvas.** `src/ui/style.rs` `tags()` (base :436–445) sets `.bg(Color::Reset)` when not selected; used at `src/components/commitlist.rs:553`.
- Trigger: amber theme, log tab, a commit with a tag, on a terminal whose default bg isn't pure black (most dark themes are `#1e1e1e`-ish, and light themes are white).
- Effect: tag label cells show the terminal's own background inside the black canvas. Before 15D the whole screen was `Reset`, so the hole was invisible. The canvas now exposes it.
- Class: new defect (old code made visible by the new canvas). Grep for siblings: no other explicit `bg(Color::Reset)` in `src/components` or `src/ui/style.rs`. The `Clear` widget used by about 25 popups also resets to `Reset`. I didn't check that each popup repaints with `popup()`/`panel_bg` after `Clear`, because the panel_bg phase owns that. See "Not checked".

**F2. Selected tab is now BOLD in the classic theme too.** `src/ui/style.rs:466–469`.
- Trigger: no theme.ron on a non-truecolor terminal, or any classic-base file.
- Effect: classic tab bar looks different from launch and upstream gitui (bold + underline vs underline only). Not a color, so the "classic keeps classic colors" line in the CHANGELOG still holds. It's still a visible classic change.
- Class: regression (looks deliberate; origin settled in the contract pass).

**F3. A theme file that mixes `Some(...)` and bare colors falls back to the whole classic theme.** `src/ui/style.rs` `load_with_notice`: patch parse fails on a bare color, and old-format parse fails on `Some(...)`. Both fail → `Self::classic()` plus an error log.
- Trigger: user copies the THEMES.md amber example (`Some(...)` values) and adds one bare value, e.g. `(base: Some("amber"), tag_fg: Some("Red"), canvas_bg: "Black")`.
- Effect: the whole file is ignored, including `base`. The new THEMES.md sentence "a file that sets `base` may write every color without `Some`" reads as per-field permission, but it's all-or-nothing.
- Class: old bug (the parser was always all-or-nothing). The doc wording in this phase makes it easier to hit.

**F4. t15e rule assertions skip the two edge columns.** `src/app.rs:4293` (`1..=(width - 2)`) and the 18×12 loop `1..=16`.
- The bottom border spans the full width, so columns 0 and `width-1` are rule cells too. A wrong style on the corners would pass.
- Class: test defect (minor).
