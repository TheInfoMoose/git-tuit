# Phase 10 review

Range: `5c02f391..832ba764`. Files: `asyncgit/src/sync/branch/mod.rs`, `asyncgit/src/sync/merge.rs`, `asyncgit/src/sync/mod.rs`, `src/popups/checkout_option.rs`.

## Independent pass

### What changed (as read from code)
1. **Bare-main worktree check** (`branch/mod.rs` `check_branch_not_checked_out_elsewhere`): a bare common repo's `HEAD` no longer counts as "checked out". Sibling linked worktrees are still checked.
2. **Untracked-in-HEAD collisions** (`branch/mod.rs` `worktree_matches_tree_entry`, `find_untracked_collisions`): an untracked path that exists in HEAD (e.g. after `git rm --cached`) is no longer a collision when its raw on-disk bytes (file) or link target (symlink) hash to the HEAD blob. Type changes, dirs, gitlinks and filtered-content mismatches stay collisions.
3. **Cleanup failure after a moved HEAD** (`branch/mod.rs` `apply_discard_checkout`, new `DiscardOutcome`): if `cleanup_state` fails after `set_head`, the call returns `Ok(StateNotCleared(msg))` instead of `Err`, so a created remote-tracking branch is no longer deleted out from under HEAD. UI (`checkout_option.rs` `discard_finished`) closes, refreshes and shows a "checkout warning".
4. **Abort keeps populated submodules** (`merge.rs`): merge-added gitlink paths are removed with `remove_dir` (kept if non-empty); a missing gitlink dir no longer counts as a local change that blocks abort.
5. Upstream-set failure on remote discard now maps to `Error::Generic("could not set upstream '…' for '…': …")`.

### Traced
- `checkout_branch_discard` end to end: target resolution → collision check → `apply_discard_checkout` → rollback of a created branch only on `Err`. On `StateNotCleared` the created branch is kept and HEAD points to it (correct: deleting it would leave HEAD dangling).
- Every caller of `checkout_branch_discard`: `confirm_discard` (real key path: Enter on Discard → `open_discard_confirm` → `ConfirmAction` → `app.rs:1196`), `handle_event` Discard arm (reachable only from tests; Enter on Discard never calls it, `checkout_option.rs:297-306`), and tests. Both prod paths route through `discard_finished`.
- Event order on warning: `Update(ALL)`, hide, `ShowErrorMsg`. `confirm_discard` did not push `SelectBranch` at base and still doesn't, so no popup ordering change on the real path.
- `find_untracked_collisions` callers: only `checkout_branch_discard`. Statuses are `WT_NEW` without ignored; a `rm --cached` path is `INDEX_DELETED|WT_NEW`, so the new branch is hit. Paths now skipped are always recoverable from HEAD, so force-overwrite/remove loses nothing that git itself would refuse to lose.
- `merge.rs` `abort_pending_state`: `to_remove` holds paths absent from HEAD; `gitlinks` covers any stage, so conflicted gitlinks (t10d_conflicted) take the keep-if-non-empty path. `worktree_matches_index` is only called from `find_blocking_local_changes` on stage-0 entries; the new "absent gitlink = matches" only stops a missing empty submodule dir from blocking. For a HEAD-file → index-gitlink path with the dir absent, restore writes the HEAD file; nothing lost.
- `io::ErrorKind::DirectoryNotEmpty` is stable since 1.83; MSRV is 1.88 (`Cargo.toml:7`).
- `FAIL_CLEANUP_STATE` is `#[cfg(test)]` and thread-local, reset by a Drop guard; no prod effect, no cross-test bleed.
- Base assertions: the one changed existing test (`checkout_option.rs` upstream-failure test) was tightened from `is_err()` to a message prefix check, not loosened.
- Sensitive data: none. Tests use `TempDir` and placeholder content.

### Findings

**F1 — test defect, low.** `src/popups/checkout_option.rs` `t10c_warning_closes_and_refreshes` / `t10c_switched_shows_no_warning` call `discard_finished` directly. The real path is `confirm_discard` (`checkout_option.rs:148`, via `app.rs:1196`). Trigger: change `confirm_discard` to drop the outcome (e.g. `.map(|_| { push Update; hide })`). Effect: both tests still pass while the user never sees the "merge state not cleared" warning. The core test (`branch/mod.rs` `t10c_cleanup_failure_keeps_switch`) proves the outcome is produced, not that the UI shows it. Fix: drive the test through `confirm_discard` (or the app's `ConfirmAction` handling) with `FAIL_CLEANUP_STATE` set — needs the hook reachable from the binary crate's tests, or an app-level test.

**F2 — new defect (minor efficiency), low.** `asyncgit/src/sync/branch/mod.rs` `worktree_matches_tree_entry` uses `std::fs::read` on every untracked-in-HEAD file. Trigger: `git rm --cached` a large binary (hundreds of MB), then discard-checkout. Effect: whole file loaded into memory on the UI thread before the switch. Rare in practice; noting rather than recommending a fix now. Streaming via `Oid::hash_file` would avoid it.

No regressions found.
