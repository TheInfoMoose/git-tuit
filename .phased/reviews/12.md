### F1 — Default theme no longer follows the terminal palette (regression, high)
- `src/ui/style.rs:12-19, 354-385` (Default impl), `THEMES.md:3-4`, `README.md:267`.
- Trigger: run with no `theme.ron` on (a) a light-background terminal, or (b) a terminal without 24-bit colour (Apple Terminal, tmux without `Tc`, Linux console).
- Effect: launch defaults were ANSI named colours / `Reset`, which the terminal palette adapts. Now every default is `Color::Rgb`. (a) `#FFD866` (focused titles, selected tab, hashes, tags, moved files) on white is roughly 1.3:1 contrast, unreadable; `#FFB000` borders/commands are little better. (b) Colours get approximated or mangled. No truecolor detection exists (`grep COLORTERM|truecolor` empty). Docs still show `assets/light-theme.png` as "default on light terminal".

### F2 — Existing user theme files silently change (regression, high)
- `src/ui/style.rs` `Theme::init` + Default impl; new fields at `style.rs:48-51`.
- Trigger: an existing patch-format `~/.config/gitui/theme.ron`, either hand-written or produced by launch's `save_patch`, which stored only the diff against the *old* defaults.
- Effect: every field the file leaves unset now resolves to amber instead of the launch default, so a user's theme mutates on upgrade. Old full-format files also lack the four new fields, so `panel_bg`, `border_focused_fg`, `scroll_track_fg`, `attention_fg` turn amber inside an otherwise custom theme. Breaks the repo's `~/.config/gitui/` compatibility rule. There's no shipped preset to get the launch look back.

### F3 — Scrollbar thumb is near-invisible (new defect, medium)
- `src/ui/scrollbar.rs:140-141` (`style_pos = scroll_bar_pos()` = `selection_bg`) with `selection_bg = #2A1A00`, `scroll_track_fg = #5C3A00`.
- Trigger: any scrollable list or diff on a dark terminal.
- Effect: the position marker is *darker* than the track it sits on and close to black, so the scroll position is hard to see. `t12b_scrollbar_track_styled` (`scrollbar.rs` ~line 183) asserts `Rgb(42, 26, 0)` for the thumb, so the test enshrines it.

### F4 — Half-migrated block chrome (new defect, low-medium)
- Helpers `styled_block`/`popup_block` (`src/ui/mod.rs:24-50`) are used only by `draw_list`, `dialog_paragraph` and `popup_paragraph` (whose only caller is `confirm.rs:141`).
- Still on their own Blocks: `diff.rs:735`, `commitlist.rs:874`, `revision_files.rs:419`, `syntax_text.rs:245`, `app.rs:1421`, `stashing.rs:165`, and popups msg, help, branchlist, fetch, push, pull, push_tags, taglist, remotelist, submodules, externaleditor, options, reset, checkout_option, log_search, fuzzy_find, blame_file, file_revlog, goto_line.
- Effect: padded titles next to unpadded ones (snapshot shows `┌ Unstaged Changes ─` beside `┌Diff: ─`); the confirm popup is Plain on `panel_bg` while the msg/help/branch popups are Thick on the terminal background.

### F5 — Theme-equality helper skips the new fields (test defect, low)
- `src/ui/style.rs` ~428-466 `assert_theme_eq`; `t12a_default_is_amber`.
- Trigger: a conversion or default bug that drops `border_focused_fg`, `scroll_track_fg`, `panel_bg` or `attention_fg`.
- Effect: `t12a_partial_old_theme_loads` and `t12a_bad_file_gives_default` would still pass. (The per-field t12b/c/d tests cover defaults and patch for each, but not old-format conversion of three of them.)
